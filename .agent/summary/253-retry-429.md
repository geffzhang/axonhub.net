# §253 通道显式列出 429 时的同通道重试

## 背景

live 提交 `c31867e0`（#2668）：`CanRetry` 的 429 分支在通道级重试规则之前
直接返回 false，因此通道 `settings.retryableStatusCodes` 中列出的 429 没有
效果。修复后 429 默认仍切换通道，只有显式列出 429 的通道才在同通道重试。

## 实现

- `PersistentOutboundTransformer.CanRetry` 在读取候选后增加
  `ChannelRetriesOn429(candidate)`：只有 `RetrySettings.RetryableStatusCodes`
  包含 429 时才跳过强制切通道，继续执行剩余模型与通道规则判断。
- 默认通道（未列 429）保持原行为：429 立即返回 false，由 Pipeline 切换通道。
- `ChannelRetrySettings` 的注释同步为“5xx 默认同通道重试；429 默认切通道，
  列出后改为同通道重试”。

## 测试

- `AChannelThatLists429OptsIntoSameChannelRetry`：
  - opt-in 的 `HttpClientError(429)` 与 `ResponseError(429)` 均允许同通道重试；
  - 未 opt-in 的两种 429 仍拒绝。

## 边界

- 只影响同通道重试判定；Pipeline 的 429 冷却与切通道预算不变。
- 429 的 opt-in 使用候选已解析的 retry settings，与请求链路同一数据源。
